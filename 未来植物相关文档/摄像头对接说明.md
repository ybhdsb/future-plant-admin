# 未来植物原型系统 · 摄像头子系统对接说明（云台 / 录像 / 拍照）

| 项目 | 内容 |
|------|------|
| 文档性质 | 软件平台与摄像头局域网网关之间的接口、数据入库与联调约定 |
| 适用对象 | 摄像头网关开发同学；软件侧后端联调与验收；指导教师审阅 |
| 默认设备标识 `deviceKey` | `camera-main-01`（逻辑设备键，映射至网关侧物理摄像头） |
| 平台服务基址（示例） | `http://<平台主机IP>:8708` |
| 摄像头网关基址（示例） | `http://<网关主机IP>:8080/api/v1`（须携带请求头 `X-API-Key`） |
| 版本说明 | 一期约定云台八向转动、录像、拍照及定时拍照；**不提供按角度精确转动** |

**分工原则：** 软件侧负责平台接口定义、指令与媒体元数据入库、前端展示；摄像头侧负责在局域网内提供 HTTP 网关并实现真实设备控制。摄像头硬件驱动、SDK 调用等内部实现不在本文范围内。

**实机能力约束（以硬件侧最新确认为准）：**

- 云台支持：八向连续转动 + **转速**（1～100）+ **转动时间**（由平台侧换算为「启动 → 等待 → 停止」）
- **不支持**按绝对角度或相对角度精确转动（设备能力不足；本期及后续规划均不纳入角度类接口）
- 网关文档中若存在角度类接口（如 `/ptz/rotate`、绝对角度设定等），**本期一律忽略**

## 1. 数据表设计（软件侧）

摄像头侧无需维护业务库。平台侧以 MySQL 存储控制指令流水与媒体资产元数据，两表通过字段 **`device_key`** 关联同一逻辑摄像头。

### 1.1 `plant_command_log`（控制指令流水表）

用于记录每一次云台、录像、拍照等操作的完整生命周期：从用户发起、平台登记、下发网关，到执行成功或失败。便于前端查询指令状态、运维排错与操作审计。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT，主键，自增 | 记录编号；对外暴露为 `commandId`，格式 `c-{id}` |
| device_key | VARCHAR(64)，非空 | 逻辑设备标识，须与 API 请求中的 `deviceKey` 一致 |
| client_request_id | VARCHAR(64) | 客户端幂等键（可选）；重复提交时可去重 |
| command_type | VARCHAR(64)，非空 | 指令类型，取值见下表 |
| payload_json | LONGTEXT | 指令参数 JSON 原文，如方向、转速、时长等 |
| status | VARCHAR(32)，非空 | 执行状态：`PENDING`（待下发）/ `SENT`（已发往网关）/ `ACKED`（成功）/ `FAILED`（失败）/ `TIMEOUT`（超时） |
| result_message | VARCHAR(512) | 执行结果说明或错误摘要 |
| operator_name | VARCHAR(64) | 操作者用户名（管理端登录用户，可空） |
| created_at | DATETIME(3) | 指令创建时间 |
| sent_at | DATETIME(3) | 平台向网关下发的时间 |
| finished_at | DATETIME(3) | 指令结束时间（成功或失败时写入） |

**本期约定的指令类型（`command_type`）：**

| command_type | 含义 |
|--------------|------|
| `GIMBAL_MOVE` | 云台按方向连续转动（转速 + 持续时间） |
| `CAMERA_RECORD_START` | 开始录像 |
| `CAMERA_RECORD_STOP` | 停止录像 |
| `CAMERA_CAPTURE` | 立即拍照 |
| `CAMERA_CAPTURE_SCHEDULE` | 启动或停止定时拍照任务 |

### 1.2 `plant_media_asset`（媒体资产元数据表）

用于登记拍照或录像产生的文件信息。表中 **`storage_path`** 指向平台可访问的最终存储位置；网关返回的本地路径须由平台侧同步或登记后写入本表，供前端浏览与下载。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT，主键，自增 | 资产编号 |
| device_key | VARCHAR(64)，非空 | 逻辑设备标识 |
| media_type | VARCHAR(32)，非空 | 媒体类型：`IMAGE`（照片）/ `VIDEO`（视频） |
| storage_path | VARCHAR(512) | 平台侧可访问的文件路径（见第 6 节「媒体文件约定」） |
| captured_at | DATETIME(3) | 拍摄或录制完成时间 |
| meta_json | LONGTEXT | 扩展元数据 JSON，如时长、分辨率、网关侧原始路径等 |
| created_at | DATETIME(3) | 平台入库时间 |

## 2. 功能需求（一期）

| 功能 | 平台对摄像头侧的要求 | 平台须获得的结果 |
|------|----------------------|------------------|
| 云台转动 | 按指定方向、转速连续转动一段时间后停止 | 执行成功或失败（**不要求**回传角度） |
| 开始 / 停止录像 | 启动录制；停止并封装保存 | 录像状态；停止后文件路径等信息 |
| 立即拍照 | 触发单次快门 | 照片文件路径等信息 |
| 定时拍照 | 按固定间隔循环拍摄 | 任务运行状态；每张照片的文件信息 |

## 3. 通信架构

摄像头侧已在局域网内提供 **HTTP 网关**（部署于网关主机，默认端口 `:8080`）。与温湿度等「边缘轮询平台」的模式不同，本期采用 **平台后端主动调用网关** 的同步/半同步模式。

```text
管理端前端发起操作
  → 调用接口① 平台 API（:8708）
  → 平台后端写入 plant_command_log
  → 平台后端调用接口② 摄像头网关 API（:8080/api/v1/...）
  → 网关在 HTTP 响应或状态查询中返回执行结果
  → 平台更新指令状态、写入 plant_media_asset（如适用），并响应前端
```

**接口分层：**

```text
接口①  前端 → 平台       表达业务意图（平台 REST API）
接口②  平台 → 摄像头网关  执行真实设备控制（网关 REST API）
```

**安全约束：** 前端 **禁止** 直连摄像头网关（`:8080`）。原因包括：浏览器跨域限制、API 密钥不可暴露于客户端、统一鉴权与审计须经平台后端。预览画面若需展示，应由 **平台后端代理转发**，不得将 `X-API-Key` 下发至浏览器。

## 4. 接口①：平台 API（供前端与管理端调用）

基址：`http://<平台主机IP>:8708`  
路径前缀：`/plant/api/camera`  
（实现时可挂载于现有 `/plant/api/commands` 体系之上；下文按语义独立列出。）

### 4.1 云台转动

| 项目 | 约定 |
|------|------|
| 方法 | `POST` |
| 路径 | `/plant/api/camera/ptz/move` |

**请求体：**

```json
{
  "deviceKey": "camera-main-01",
  "direction": "up_left",
  "speed": 30,
  "durationMs": 500
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| deviceKey | 是 | 逻辑设备键 |
| direction | 是 | 转动方向，见下表 |
| speed | 是 | 转速，整数 1～100 |
| durationMs | 是 | 转动持续时间，单位毫秒 |

| direction | 含义 |
|-----------|------|
| `up` / `down` / `left` / `right` | 上 / 下 / 左 / 右 |
| `up_left` / `up_right` / `down_left` / `down_right` | 左上 / 右上 / 左下 / 右下 |

**成功响应示例：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "commandId": "c-2001",
    "status": "ACKED"
  }
}
```

> 说明：平台 **不提供**「转动指定角度」类接口；`durationMs` 由平台后端翻译为网关侧的 `move` + 等待 + `stop` 时序（见第 5.4.3 节）。

### 4.2 开始录像

|------|------|
| 方法 | `POST` |
| 路径 | `/plant/api/camera/recording/start` |


### 4.3 停止录像

| 项目 | 约定 |
|------|------|

| 路径 | `/plant/api/camera/recording/stop` |


## 5. 接口②：摄像头网关 API（供平台后端调用）

> 本节为对接备份清单，仅列 **本期可用** 的网关接口。  
> 基址：`http://<网关主机IP>:8080/api/v1`  
> 以下路径均相对于该基址。

### 5.0 通用约定

| 项目 | 约定 |
|------|------|
| 协议 | HTTP（局域网） |
| 认证 | 每个请求须携带请求头 `X-API-Key: <密钥>` |
| JSON 正文 | 有请求体时须设置 `Content-Type: application/json` |
| 调用方 | **仅平台后端**（Java 服务）；浏览器不得直连 |
| 密钥管理 | 密钥存放于网关侧 `.runtime/api-key.txt`，线下交接，不得进入版本库或前端代码 |

**公共错误响应：** 正文多为 `{"detail":"错误说明"}`。

| HTTP 状态码 | 含义 | 平台侧处理建议 |
|-------------|------|----------------|
| 401 | 密钥缺失或错误 | 检查平台配置的 `X-API-Key` |
| 403 | 跨站或权限拒绝 | 确认由后端调用，非浏览器直连 |
| 404 | API 未启用或资源不存在 | 确认网关服务已启动（如 `start-api.cmd`） |
| 409 | 未连接 / 冲突 / 设备忙 | 先调用 `GET /status`，避免盲目重试转动 |
| 422 | 参数不合法 | 修正请求参数 |
| 501 | 设备不支持该能力 | 勿调用角度类接口 |

**请求：**

| `recording` | 录像状态摘要 |
| `photos` | 拍照 / 定时任务摘要 |

平台侧判断「相机是否在线」时，优先参考本接口。

### 5.4 云台：方向 + 转速 + 转动时间（本期核心）

实机约定：**仅支持八向 + 速度 + 时间**；不支持角度控制。

#### 5.4.1 开始转动 `POST /ptz/move`

```http
POST /api/v1/ptz/move
X-API-Key: YOUR_API_KEY
Content-Type: application/json

{"direction":"up_left","speed":30}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| direction | string | 转动方向，见下表 |
| speed | int | 1～100，默认约 30，表示转速百分比 |

| direction | 含义 |
|-----------|------|
| `up` | 上 |
| `down` | 下 |
| `left` | 左 |
| `right` | 右 |
| `up_left` | 左上 |
| `up_right` | 右上 |
| `down_left` | 左下 |
| `down_right` | 右下 |

**成功：** HTTP 200，返回云台状态 JSON。

#### 5.4.2 停止转动 `POST /ptz/stop`

```http
POST /api/v1/ptz/stop
X-API-Key: YOUR_API_KEY
```

无请求正文。松开控制或转动结束时须调用，避免云台持续转动。

#### 5.4.3 平台实现「转动 durationMs 毫秒」的时序

网关侧为「连续转动 + 心跳 / 停止」模型；**转动时长由平台后端控制**：

```text
1. POST /ptz/move   { direction, speed }
2. 等待 durationMs（例如 500）
3. POST /ptz/stop
```

补充说明：

- 网关文档要求连续控制时，约每 250 ms 可重发同一 `move` 作为心跳；超过约 1 秒无心跳可能自动停止。短时间转动（如 &lt;1 s）按上述三步即可。
- 长时间按住：平台后端循环发送 `move` 心跳，松手或到时发送 `stop`。
- **禁止**使用角度类接口近似实现「转动时长」。

对应平台接口①：`direction` + `speed` + `durationMs` → 平台后端翻译为上述时序。

### 5.5 录像

#### 5.5.1 开始 `POST /recording/start`

```http
POST /api/v1/recording/start
X-API-Key: YOUR_API_KEY
```

无请求正文。返回录像状态；`phase` 可能先为 `starting`，收到首帧后为 `recording`。

#### 5.5.2 停止 `POST /recording/stop`

```http
POST /api/v1/recording/stop
X-API-Key: YOUR_API_KEY
```

无请求正文。停止后须封装 MP4，**不能**认为本响应即表示文件已就绪。

#### 5.5.3 状态 `GET /recording/status`

轮询直至结束：

```http
GET /api/v1/recording/status
X-API-Key: YOUR_API_KEY
```

**`phase` 取值：** `idle` / `starting` / `recording` / `stopping` / `finalizing` / `saved` / `error`

**`saved` 时平台侧关注字段示例：**

```json
{
  "phase": "saved",
  "message": "录像已保存为 MP4",
  "started_at": 1234567890,
  "duration": 60.0,
  "file": "D:\\...\\recordings\\示例.mp4",
  "directory": "D:\\...\\recordings"
}
```

| 字段 | 说明 |
|------|------|
| duration | 录像时长，单位秒 |
| file / directory | **网关主机本地路径**，非 HTTP 下载 URL |

**「录制 N 秒」推荐流程：** `start` → 平台等待 N 秒 → `stop` → 轮询 `status` 直至 `phase` 为 `saved` 或 `error`（封装过程最多可等待数分钟）。

录像进行中勿调用 `switch` / `disconnect`（可能返回 409）；应先停止录像并等待 `saved` / `error`。

### 5.6 拍照与定时拍照

#### 5.6.1 立即拍照 `POST /photos/capture`

```http
POST /api/v1/photos/capture
X-API-Key: YOUR_API_KEY
```

无请求正文。

**成功时平台侧关注字段：**

| 字段 | 说明 |
|------|------|
| file | 网关主机本地照片路径 |
| captured_at | 拍摄时间（含时区） |
| camera | 相机标识 |
| source | 来源，如 `preview` |
| bytes | 文件大小（字节） |

无预览或画面过旧时可能返回 409。网关 **不提供** 文件 HTTP 下载接口；平台须按第 6 节约定同步或登记文件。

#### 5.6.2 定时拍照启动 `POST /photos/schedule/start`

```http
POST /api/v1/photos/schedule/start
X-API-Key: YOUR_API_KEY
Content-Type: application/json

{"interval_seconds":10}
```

| 字段 | 说明 |
|------|------|
| interval_seconds | 间隔秒数，允许 1～86400（可为小数）；首次拍摄在一个间隔后触发 |

重复调用 `start`：更新间隔并重新计时，不创建第二个并行任务。

#### 5.6.3 定时拍照停止 `POST /photos/schedule/stop`

```http
POST /api/v1/photos/schedule/stop
X-API-Key: YOUR_API_KEY
```

无请求正文。已拍摄文件保留在网关侧目录。

#### 5.6.4 状态 `GET /photos/status`

常用字段：`active`、`interval_seconds`、`count`、`session_count`、`failures`、`directory`、`last_file`、`last_captured_at`、`next_in_seconds`、`message`。

`GET /status` 中亦会携带 `photos` 摘要。

## 6. 媒体文件约定

网关返回的 `file` 字段为 **网关主机本地绝对路径**，平台无法直接以 URL 形式提供给前端。联调时须约定以下之一：

| 方案 | 说明 |
|------|------|
| 平台主动拉取 | 平台后端通过共享目录、SFTP 等方式，将文件复制至平台存储后写入 `plant_media_asset.storage_path` |
| 网关推送 | 网关拍照 / 封装完成后，将文件上传至平台指定接口或共享存储（若二期扩展） |
| 元数据先行 | 短期内可先入库 `meta_json` 中的网关原始路径，待文件同步完成后再更新 `storage_path` |

**`plant_media_asset.storage_path` 填写规则：** 须指向 **平台侧可访问** 的最终路径；前端展示与下载均经平台 API，不得直连网关文件路径。

## 7. 验收标准

| 序号 | 验收项 | 通过条件 |
|------|--------|----------|
| 1 | 通信分层 | 前端仅调用平台 `:8708`；平台后端调用网关 `:8080` |
| 2 | 云台控制 | 八向 + 转速 + 时长可执行；无角度类接口被调用 |
| 3 | 录像 | 开始 / 停止 / 状态轮询正常；`saved` 后元数据入库 |
| 4 | 拍照 | 立即拍照与定时拍照均可触发；照片元数据入库 |
| 5 | 指令追溯 | `plant_command_log` 中可查询指令状态与结果 |
| 6 | 密钥安全 | `X-API-Key` 未出现在前端代码或浏览器请求中 |
